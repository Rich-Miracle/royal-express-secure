STEP 4 - PUBLIC ENDPOINT HARDENING
==================================

Replaces server/inc/get.php and server/inc/add.php. Extract over the existing
files, then commit.

WHAT THIS FIXES
---------------
Five functions reachable without a session were still building SQL by string
interpolation, so the application remained injectable to an unauthenticated
attacker even after the login was fixed:

  checkArea()         public pricing form
  checkAreaByName()   area lookup
  checkUserEmail()    registration email availability check
  getAllcustomerById() customer record lookup
  addMessage()        public contact form
  createCustomer()    public registration

All are now prepared statements with bound parameters.

createCustomer() also had a second and more serious fault. It wrote the
password into the customer table exactly as typed. Migrating the existing rows
to bcrypt did not fix this, because every new registration since then created
another plaintext row behind the migration. It now hashes on insert.

If you registered any test accounts after running the migration, their
passwords are sitting in the table as cleartext. Re-run the migration to
convert them:

  ..\..\php\php.exe tools\migrate_passwords.php

Input validation was added to both public forms: email format, field lengths,
a minimum password length of 8, a permitted set for gender, and a duplicate
address check on registration.
